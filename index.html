Problem

Existing AI tools are built for developers, not for the corner-shop owner, the elderly parent, or the visually impaired user.

Digital accessibility in Indonesia isn't just about language. There are four layers preventing today's AI from being truly usable by the majority population.

01 / Language

Local context lost

Global models don't understand local trade idioms or the Bahasa-Javanese-Sundanese mix used daily by market sellers.

02 / Interface

Typing is a barrier

Many MSME owners are elderly, visually-impaired, or simply uncomfortable typing long messages. Voice-first is the prerequisite for actual adoption.

03 / Channel

Web/app is too far

They already live on WhatsApp and Telegram. Forcing a new app install with multi-step onboarding nearly always fails in this market.

04 / Cost

Premium APIs aren't realistic

Average warung owner margin: Rp 500k–2M / month (US$30–125). A US$20+/month AI tool will never get used.

Philosophy

Accessibility first, not as an afterthought.

Sanak is built with WCAG AA as baseline and voice-first as the primary modality — not bolted on later. What's designed for visually-impaired users ends up more comfortable for everyone.

VO

Voice-first, not voice-added

Every feature is fully accessible by voice — commands, navigation, confirmation, correction. Typing is only an alternative.

SR

Screen reader compatible

TalkBack, VoiceOver, NVDA, JAWS — tested across all major AT. Semantic HTML, ARIA roles, alt text written by humans.

CL

Plain language, not jargon

"Got it, today's capital is Rp 50,000" — not "Transaction logged: COGS=50000 IDR". Human tone, plain-language guideline.

CT

High contrast & large hit targets

Minimum 4.5:1 contrast ratio. Buttons minimum 44×44px. Default font size 18px+. Reduced-motion support.

OL

Works on weak signal

Optimized for 3G/EDGE connections still common in non-urban Indonesia. Local cache for frequent voice commands.

Agent capabilities

A real agent — not a glorified chatbot.

Sanak orchestrates tools across multiple steps to complete real-world tasks. Function calling, structured output, multi-turn reasoning — every action is observable, every step is reproducible.

Built-in tool registry

  • read_ledger Query encrypted bookkeeping store with date range, category filters, aggregations.
  • log_transaction Parse natural-language entry into structured row: amount, type, category, timestamp.
  • calculate_margin Cost basis breakdown, suggested selling price, breakeven volume from cost inputs.
  • describe_image Multimodal vision — product photo to caption, document scan to summary, scene narration.
  • draft_caption Generate platform-aware copy for Shopee, TikTok, Instagram with relevant hashtags.
  • draft_reply Compose customer message replies in matching tone, await user approval before sending.
  • read_document Parse PDFs, scans, screenshots — bills, invoices, government forms — and explain plainly.
  • schedule_reminder Proactive: stock-low notifications, weekly summary push, payment-due reminders.

Architecture

From spoken word to spoken answer.

How Sanak handles a single voice message — across channel, edge runtime, agent core, tools, memory, and back to voice. Average end-to-end latency under 3 seconds.

Channel layer

WhatsApp Business API + Telegram Bot API. Message ingress and TTS output back to user, no install required.

Edge runtime

Local cache, retry queue, weak-signal handling. Voice cached for offline replay, transcripts queued when network drops.

Agent core

Orchestrator + planner. Decomposes intent, calls tools in sequence, recovers from errors, formats human-friendly response.

Tool registry

8 callable tools — bookkeeping, captions, vision, document parse, proactive notifications. Each tool sandboxed with structured I/O.

Memory layer

Three tiers — working, episodic, semantic. End-to-end encrypted per user. No cross-user training data exposure.

Model tier

Cost-efficient small model handles 80% of requests. Escalates to flagship LLM only for complex reasoning or vision tasks.

Memory architecture

Three-tier memory, encrypted per user.

Sanak doesn't store conversation logs in plaintext. Each user gets a dedicated key; memory is partitioned by purpose; recall is grounded against verifiable sources before the agent acts.

Tier 1 — Working

Conversation context

Last N turns kept in-flight for the current session. Cleared on session close. Used for pronoun resolution and short-term task continuity.

in-memory · session-scoped
Tier 2 — Episodic

Per-user history

Past interactions, decisions, corrections. Encrypted at rest with per-user keys. Indexed for semantic recall — "remember when I said X" works without scanning all chats.

vector store · AES-GCM encrypted
Tier 3 — Semantic

Business knowledge graph

Structured facts about the user's business — products, suppliers, customers, prices, hours, dialect preferences. Updated by agent observations, queryable as graph.

graph DB · entity-relation
Query: "Berapa harga keripik singkong yang biasa aku jual?" ↓ Recall: Tier 3 graph lookup → product:keripik_singkong ↓ Augment: Tier 2 episodic → recent price changes (last 30d) ↓ Ground: cite source row from ledger, not hallucinated ↓ Respond: "Rp 15.000 per pack, terakhir dinaikkan dari 13.500 dua minggu lalu."

Safety & guardrails

Safe by design — not by accident.

An assistant that reaches the elderly, the visually impaired, and small-margin businesses must be careful by default. Every guardrail below is a hard constraint, not a wishlist.

Content

Content moderation

Hate speech, NSFW, harmful instructions, and harassment are filtered at input and output. Indonesian-context-aware — local slurs and dog-whistles are caught alongside English.

Advice

Conservative on financial / legal / medical

No investment recommendations, no legal opinions, no medical diagnoses. Sanak helps with bookkeeping and pricing, not "should I take this loan." Hard refusal with redirect to qualified human.

Privacy

End-to-end memory encryption

User memory — transactions, customer notes, business context — is encrypted with per-user keys before leaving the device. The server cannot read business data, even if compromised.

Hallucination

Cited tool outputs, confidence labels

When Sanak gives a number, the source tool call is shown in the audit trail. Uncertain answers carry an explicit "I'm not sure" prefix. Numbers are never invented.

Injection

Prompt-injection sandbox

Tool inputs are validated against a strict schema. Customer messages are quoted, not interpreted as commands. A customer typing "ignore previous instructions" cannot make Sanak send their data elsewhere.

Confirmation

User confirmation before send

Outbound actions — replying to customers, sending invoices, posting to social — always require explicit user confirmation. Drafts shown in plain language, never auto-sent.

Audit

Tool-call audit trail

Every tool call is logged client-side with timestamp, inputs, and outputs. Users can review their full history and revoke specific actions retroactively.

Refusal

Honest "I can't help with that"

When Sanak hits its limits, it says so plainly and suggests a next step — human contact, retry phrasing, alternative tool. Never invents a workaround.
